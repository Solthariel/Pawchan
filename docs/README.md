## Обязательные требования, не отчёты

[AGENTS.md](../AGENTS.md) хранит общие требования архитектуры, качества и поставки.
Тематические разделы сохраняют силу прежних правил:

- [MODULE_BOUNDARIES](contracts/MODULE_BOUNDARIES.md) — зависимости, владельцы, ресурсы и перенос модулей.
- [SOURCE_ADAPTERS](contracts/SOURCE_ADAPTERS.md) — адреса, возможности, изоляция источников.
- [UI_BEHAVIOR](contracts/UI_BEHAVIOR.md) — состояние UI, протоколы и схема поста.
- [PERFORMANCE](contracts/PERFORMANCE.md) — hot path, текст/превью/поиск и протокол замеров.

Руководство не может отменять обязательный контракт. Противоречия нужно разбирать,
а не обходить. Порог Detekt не правится ради зелёного результата.

## История отдельно от актуальных инструкций

[docs/history](history/README.md) содержит снимки патчей и их проверок с исходными
ограничениями. Старые числа тестов, PASS/FAIL и команды относятся к своей базе.
Их нельзя использовать как текущий статус или выполнять как инструкцию выпуска.
Результаты в старых тематических руководствах также не заменяют новый прогон.

## Как не наращивать процесс

Перед добавлением документа обновите существующее руководство по ответственности.
Не нужен отдельный постоянный HOWTO для каждой мелкой правки: описание изменения
может остаться в коммите/PR, результат проверки — в отчёте CI. Новый постоянный
документ нужен для самостоятельной темы, не для повторения версии или числа тестов.
Это порядок ведения документации, не отмена тестов, отчётности или LOCAL CHECK.

Один факт должен иметь понятный источник: общие правила — AGENTS/contracts,
команды проверок — DEVELOPMENT, публикация — RELEASE_PROCESS, номер — versions.json.
В остальных местах ставьте ссылку вместо копии инструкции. При переносе обновляйте
ссылки и сохраняйте ограничения/происхождение; чужие лицензии не удаляются.
