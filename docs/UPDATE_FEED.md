# Публикация APK и обновлений

В release assets публикуются только `Pawchan-VERSION.apk` и `.apk.sha256`.
Архивы Source code (zip/tar.gz) добавляет сам GitHub; workflow их не удаляет.

Приложение по умолчанию читает:
`https://raw.githubusercontent.com/Solthariel/Pawchan/master/update/feed/data-v1.json`.
Параметр Gradle `pawchan.updateManifestUrl` и переменная
`PAWCHAN_UPDATE_MANIFEST_URL` по-прежнему могут переопределить адрес.

После успешных LOCAL CHECK, проверки подписи и SHA-256 workflow:
1. Готовит манифест из фактически собранного подписанного APK.
2. Создаёт draft-релиз с APK и контрольной суммой, затем публикует его.
3. Записывает `update/feed/data-v1.json` и `update/feed/changelogs/CODE.txt`
   обычным коммитом в master. Других веток на GitHub не создаётся.

Токен GitHub Actions требует contents:write и разрешённый push в master.
Защита ветки может запретить этот push: правила безопасности не обходятся.
Публикация релиза и коммит feed не являются одной атомарной транзакцией;
при сетевой ошибке или запрете push операция остановится. Не удаляйте тег
и не повторяйте замену вслепую: сначала проверьте лог шага публикации.

## Однократная замена первого выпуска

`update/publishing/release-request.json` явно разрешает заменить только
релиз 0.1.0 (code 1), ID 416629199, со старым тегом на коммит
0f409e09874cc85daddbbb62f865f23860075f33. Это согласованное владельцем
переиздание первого выпуска до распространения APK. Новая версия APK
подписывается прежним ключом. Установки старого APK требуют ручной переустановки
обновления, потому что в них сохранён прежний URL манифеста.

Старый релиз и тег не удаляются на компьютере установщиком. Их изменение
происходит только на GitHub после успешной сборки и повторной проверки ID
и старого коммита. Если релиз/тег уже изменились, операция останавливается.
Тег переносится на исходники новой сборки, master никогда не force-pushится.

Нельзя запускать старый Publish-Pawchan-0.1.0.ps1. Новый установщик отправляет
точечные изменения и release-request, что запускает workflow автоматически.
Запуск workflow_dispatch на master выполняет тот же release-request;
повторная замена после успеха блокируется проверкой старого ID/тега.

## Следующий выпуск

Увеличьте versionCode и versionName в versions.json и добавьте согласованные
release notes по правилам проекта. Удалите поле replace_first_release из
release-request.json и укажите новую version/code. Коммит изменения запроса
в master сам запускает публикацию. Можно вместо запроса отправить новый
тег vVERSION. Уже существующий релиз без специального разрешения не заменяется.
Рабочий манифест в update/publishing/manifest остаётся шаблоном; опубликованный
feed не используется как шаблон для упаковки другого APK той же версии.

## Проверки этой поставки

Изменены только настройки адреса и публикации, не код функций приложения.
Проверяются actionlint, Bash-синтаксис шагов, ktlint для app/build.gradle.kts,
и unit-тесты скрипта публикации. Полная Android-сборка, работа токена и
фактическая публикация выполняются GitHub Actions после команды владельца.
Локальная среда поставки не содержит полного требуемого Android SDK/NDK;
полный LOCAL CHECK и тестирование на телефоне здесь не выполнены.
