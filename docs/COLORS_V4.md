# Палитры colors-v4 и обычные обновления

Статус: исходники для проверки. Полная Android-сборка, телефонные и performance
проверки в среде помощника недоступны; публикация не выполнялась.

## Десять готовых вариантов

| Название | Стабильный ключ настроек | Изменение |
| --- | --- | --- |
| Лавандовая | LAVENDER | Без изменения цветов |
| Васильковая | BLUE | Мягкий сине-фиолетовый вместо прежнего синего |
| Оливковая | OLIVE | Приглушённая желтовато-зелёная по образцам |
| Персиковая | PEACH | Без изменения цветов |
| Пудровая | ROSE | Нежное розово-персиковое направление, не Сливовая |
| Коралловая | BURGUNDY | Тёплое красное направление вместо Бордовой |
| Ванильная | AMBER | Мягкий кремово-жёлтый вместо Янтарной |
| Мятная | GREEN | Прохладный пастельный зелёный вместо прежнего зелёного |
| Бирюзовая | TEAL | Светлый голубовато-бирюзовый образец |
| Галечная | GRAY | Почти нейтральный серый, без чёрно-белых primary акцентов |

Идентификаторы enum/DataStore/backup намеренно не переименованы: существующие
выборы переходят на новые соответствующие палитры без сброса настроек. Пользовательский
seed, режим и AMOLED сохраняются. SYSTEM и CUSTOM не входят в число десяти пресетов.
Отдельных Сливовой, Шалфейной и Янтарной в новом списке нет.

Образцы пользователя относятся к пастельному направлению, а не ко всем ролям сразу:
контрастные кнопки и текст не должны совпадать со светлой подложкой. Для восьми новых
пресетов DynamicScheme получает явные TonalPalette: primary chroma 2–40, secondary
не более 12, tertiary не более 16, neutral не более 4, neutralVariant не более 6.
Мятная/Бирюзовая имеют chroma 24. Обычный Tonal Spot поднял бы её до 36 независимо
от бледности seed. Ошибки и семантические цвета текста не перекрашиваются в акцент.
Вычисление остаётся внутри существующего remember владельца темы, не в строках ленты.

## Обновления

App больше не задаёт privateRepository и не создаёт хранилище доступа. Поэтому
UpdatePanel не показывает «Закрытые обновления», поле GitHub token и кнопки доступа.
Используется обычный HTTPS feed и штатные действия проверить/скачать/установить.
Лента истории изменений также использует обычный адрес без приватной ветки.
BuildConfig.PRIVATE_UPDATE_REPOSITORY удалён. Внутренняя опциональная реализация
приватного доступа в модуле update остаётся не подключённой к приложению.

Текущий fallback URL feed сохранён, без выдумывания нового публичного репозитория.
Для закрытого GitHub ожидается ошибка проверки, а не предложение ввести токен.
В будущем публичная версия должна получить собственный feed через существующее
pawchan.updateManifestUrl / PAWCHAN_UPDATE_MANIFEST_URL и свою конфигурацию выпуска.
Чужой публичный feed не гарантирует совместимость пакета и подписи.

Проверка HTTPS, ограничения размера, SHA-256, package/signature/minSdk, атомарная
загрузка, отмена и установка сохранены. Токен в APK не вшит; ключ подписи не меняется.
Старый PAT не отзывается на GitHub и локальный зашифрованный файл не удаляется:
приложение больше не читает его при обычных обновлениях.

## Проверка на устройстве

1. Проверить все десять палитр в светлом/тёмном/AMOLED, особенно Мятную и Бирюзовую.
2. Проверить что выбранная старая GREEN/AMBER/ROSE сохраняет выбор после обновления
   и получает соответственно Мятную/Ванильную/Пудровую; экспорт/импорт не теряет RGB.
3. RGB preview должен обновляться при движении, неполный HEX не очищать последний кадр.
4. В «О программе» нет раздела токена; проверка закрытого feed возвращает обычную ошибку.
5. Прогнать LOCAL CHECK, три Python-набора, полный device-smoke и проверить свежие отчёты.
   Предыдущие PASS не подтверждают новые исходники. Для сохранившихся v3 text/hot-path
   изменений требуется release macrobenchmark. Не публиковать до полного прогона
   и отдельного разрешения владельца.
