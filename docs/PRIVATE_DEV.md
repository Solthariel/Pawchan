# Pawchan Dev — закрытый рабочий клиент

## Что изменено

Рабочая release-сборка этого репозитория теперь называется **Pawchan Dev**,
applicationId — `com.solthariel.pawchan.dev`. Это **Release** с R8/minification
и resource shrinking, `debuggable=false`, а не переименованный Debug.
Она устанавливается рядом с прежним `com.solthariel.pawchan` с отдельными данными.
Данные, настройки и закладки не переносятся автоматически. Debug для обязательных
instrumented tests остаётся `com.solthariel.pawchan.debug` и не заменяет Dev.
Иконка сохранена: новый публичный бренд и его репозиторий — отдельная задача.
Строки настроек восстановлены на ListItem из 0.1.48; остальные интерфейсные
исправления сохранены.

## Закрытые обновления внутри приложения

Поток остаётся прежним: «О приложении» → обновления → проверить → скачать →
установить через системный установщик Android. После первого ввода доступа
скачивать APK вручную с GitHub не требуется. Токен не отменяет подтверждения
Android на установку и разрешения установки из этого источника.

В блоке «Закрытые обновления» один раз вводится **fine-grained GitHub token**:
владелец `Solthariel`, Only select repositories → **Pawchan**,
Repository permissions → **Contents: Read-only**. Не выдавайте Write/Admin или
доступ ко всем репозиториям. Срок действия задаётся на GitHub; после истечения
или отзыва токена потребуется новый. Сам репозиторий остаётся источником
`Solthariel/Pawchan`; URL сайта `pawchan.dev` здесь ни при чём.

Токен не является ключом подписи APK. Он не вшивается в APK/BuildConfig,
не передаётся через Gradle, release-request, GitHub Actions, чат или отчёт.
Хранение: AES-GCM, ключ Android Keystore, зашифрованный файл в noBackupFilesDir,
привязка к applicationId. Поле ввода маскировано и не сохраняется через
rememberSaveable. «Удалить доступ» удаляет локальный файл, но не отзывает токен
на GitHub: при утечке отзовите его там.

Манифест/заметки читаются через GitHub Contents API, APK — через authenticated
Release Assets API. Авторизация допускается только для HTTPS API настроенного
репозитория. Перенаправления проверяются на каждом шаге, токен не отправляется
CDN или другому репозиторию. Проверки SHA-256, размера, packageName, versionCode
и сертификата APK сохранены. История старых изменений берётся из встроенного
JSON, актуальные заметки приходят вместе с закрытым предложением обновления.

## Первый переход и подпись

**Не устанавливайте локальный APK, подписанный временным debug-ключом, как
основной Dev**, если дальнейшие обновления будут подписываться CI release-ключом.
Android потребует одинаковый сертификат у первой установки и всех обновлений.
Существующий механизм release signing сохранён: CI использует текущие signing
secrets; локальная сборка без них по-прежнему использует debug signing для
проверок. Старый публичный APK менять и переподписывать не надо.

После полного прогона и отдельного разрешения владельца первый Dev APK выпускается
штатным CI **со следующим versionCode**, с тем же ключом, что и будущие Dev.
Текущая история версий и release-request в этом патче не изменены; не заменяйте
уже опубликованный 0.1.49 другим APK. Первый Dev надо установить один раз;
последующие обновления доступны внутри приложения после настройки токена.
Для закрытого репозитория проверьте доступность Actions и лимиты вашего плана.

Закрыть GitHub-репозиторий должен владелец. Смена packageName сама по себе не
закрывает исходники или APK. Пока репозиторий публичен, старые клиенты могут
видеть его обновления. После перевода в private анонимные запросы старого клиента
не получат новые данные. Это не отзывает уже скачанные APK и копии исходников;
пользователь с выданным доступом к private repo также сможет их читать.
Вернуть репозиторий в public позже означает снова открыть содержимое.

## Обязательная проверка

Порядок AGENTS.md не изменён: LOCAL CHECK → три Python-набора → полный
`device-smoke` всех **8** модулей → проверка свежих отчётов → отдельное разрешение
владельца на push/публикацию. В update добавлены четыре Android runtime-теста
UI/Keystore; полный инвентарь теперь **436** тестов. Это ожидаемый состав, а не
заявление о выполнении. Основные проверки по-прежнему запускают Debug как
instrumentation target; это техническая проверка, а не требование тестировать
плавность Debug вместо Release.

Дополнительно на подписанном Dev нужны реальные сценарии: неверный/отозванный
токен, проверка без доступа, сохранение/удаление доступа, предложение следующей
версии, загрузка из private repo и установка поверх Dev с сохранением данных.
Проверить coexistence со старым Pawchan. В новой установке на текущем versionCode
без более свежего опубликованного Dev предложения обновления не будет.

Изменения ограничены изоляцией Dev и доступом к updater: инфраструктура HTTP,
шифрования, UI и их тесты остаются в существующем update-модуле; app только
передаёт конфигурацию. Новых production-зависимостей и глобальных синглтонов нет.
