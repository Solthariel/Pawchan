# Возврат к месту чтения (0.1.22)

## Контракт

- Перед адресным переходом к посту app-host захватывает текущий пост и pixel offset
  из immediate reading memory, иначе из сохранённой вкладки/копии. requestedPost
  ещё не назначен: целевой пост не может стать точкой исходного чтения.
  Pending jump содержит полный адрес и привязывается к новой screen session:
  уходящий экран и экран другого треда не применяют и не потребляют его.
  Он сохраняется через первоначальную загрузку до появления целевого поста.
  Если пост ещё не попал в кэш, позиция не сбрасывается: ожидается текущая
  загрузка и при необходимости выполняется один дополнительный refresh без
  отмены уже запущенного запроса. Явный возврат отменяет отложенный переход.
- Переход из «Ответов» и нового reply notification использует первый непрочитанный
  ответ. Для уже прочитанных ответов без target сохраняется обычное открытие треда.
  Обычные уведомления о новых постах остаются обычным открытием.
- Все адресные внешние переходы к постам пользуются той же защитой позиции.
- Точка возврата отдельна от текущей прокрутки, seen/unread и истории постов.
  Чтение после ответа сохраняет текущую позицию как раньше; обычное повторное
  открытие восстанавливает её, не заставляя вернуться к исходному посту.
- Первый незавершённый возврат имеет приоритет. Последующие переходы не меняют
  его, в том числе если две команды поставлены в очередь до завершения записи.
- Меню треда «Вернуться к месту чтения» восстанавливает пост по ID и pixel offset.
  После завершения scrollToItem сохраняется текущая позиция и удаляется именно
  использованная точка (compare-and-remove). Запись позиции и удаление точки
  выполняются одной транзакцией. Старый отложенный debounce не может перезаписать
  восстановленную позицию. Отменённый scroll точку не удаляет.
- Если поста нет в загруженном/отфильтрованном наборе, выводится пояснение;
  позиция не сбрасывается к ОП-посту, точка сохраняется для последующей загрузки.
- Точка обозначается тонкой линией поверх верхнего края поста, без изменения
  геометрии карточки, и маркером secondary на ПРАВОЙ полосе прокрутки. У поста
  есть accessibility state «Место чтения». После возврата обе отметки исчезают.
- Нет отдельного режима чтения, автоматического возврата или нового диалога.
  Обычный Back сохраняет прежнюю навигационную семантику.

## Владельцы и совместимость

WorkspaceController остаётся единственным владельцем I/O и очереди записи.
ThreadReadingSession передаёт только позицию/поток возврата, не workspace state.
Screen scope владеет скроллом и отменяется при уходе. Настройка rememberPosition
управляет созданием точек. Ключ включает site/board/thread; до 500 тредов.
Необязательное JSON-поле readingReturns сохраняется в существующем workspace
version 1; старые файлы читаются без миграции и сброса. Операции обычного чтения
и обновления постов не изменяют точки. Transfer избранного не переносит личные
точки прокрутки; полная копия workspace сохраняет их в штатном файле.

Prepared own/reply индексы scrollbar теперь строятся вместе с post navigation,
а не при композиции списка; точка возврата добавляется через O(1) lookup по ID.
Новый notification query отделяет ответы от обычного наблюдения; старые ссылки
без query и HTTP-ссылки продолжают работать как раньше.
