# Диагностика открытия медиа

Статус: диагностический патч для проверки, не исправление задержек и не performance PASS.
Версия приложения не меняется. Сетевые политики, приоритеты, кэши, декодеры,
проверка длительности и предзагрузка работают как раньше. Новых запросов нет.

## Включение и выключение

Измерения выключены, пока Android-тег `PawchanMediaTiming` не разрешает DEBUG.
Флаг читается при создании операции: включение посреди уже открытого видео
не добавит события к старой операции. Поэтому после начала записи откройте медиа заново.
Не включайте тег постоянно в обычной работе.

После обязательных LOCAL CHECK, трёх Python-наборов и всех семи device-модулей
установите из проверенной папки изолированную debug-сборку:

```powershell
& .\gradlew.bat :app:installDebug --warning-mode=fail
if ($LASTEXITCODE -ne 0) { throw 'Install failed' }
python -B .\scripts\performance\media_timing.py --seconds 120
```

Сборщик ищет ADB в PATH, переменных SDK, `local.properties` и стандартной Windows-папке SDK.
При необходимости укажите `--adb "C:\путь\platform-tools\adb.exe"` и `--serial`.
Он требует одно авторизованное устройство, не устанавливает APK, не удаляет данные,
не очищает logcat/кэши и не публикует ничего. Записывается только один диагностический тег.
После записи восстанавливается прежнее значение тега. Ctrl+C завершает запись раньше.
Если процесс принудительно убит или телефон отключён при восстановлении, выполните:

```powershell
adb shell setprop log.tag.PawchanMediaTiming ""
```

Если тег был настроен ранее, верните его прежнее значение вместо пустого.
Отключение действует для новых операций; уже созданные ограниченные probes могут
закончить запись. Для немедленного прекращения их логирования закройте диагностическое приложение.

## Первый сценарий

Debug установлен отдельно: настройки и авторизация обычного приложения в него не переносятся.
При необходимости выставьте те же настройки предзагрузки вручную.

1. Закройте другие экземпляры Pawchan; не открывайте одновременно release и debug.
2. Начните запись, затем откройте диагностическое приложение.
3. Откройте видео, на котором заметна задержка; дождитесь кадра, немного воспроизведите, закройте.
4. Откройте картинку с задержкой и дождитесь оригинала.
5. Повторите открытие каждого файла. Укажите, были ли включены предзагрузки видео и картинок.
6. Пришлите ZIP из строки `SEND REPORT`, порядок действий и какой файл задержался
   (можно описать порядковым номером без передачи самого медиа).

Сначала собираем свидетельства в debug, а не доказываем ускорение. Для сравнения
предзагрузки нужны отдельные сопоставимые записи с включённой и выключенной настройкой.
Не называйте повторное открытие «холодным», если файл мог остаться в дисковом кэше.
Не используйте `pm clear`: для этой диагностики не нужно удалять настройки и авторизацию.
Для вывода о производительности далее требуется недебажная/profileable сборка,
одинаковые данные/сеть/состояние кэшей, минимум пять повторов и применимые trace/benchmark
по [контракту производительности](../contracts/PERFORMANCE.md).

## Формат и ограничения

`probe` — временная identity-метка объекта, не URL и не хэш URL. Это не глобально
уникальный идентификатор между запусками; редкая коллизия возможна. `elapsed_ms` — время
от создания probe по монотонным часам. Операции разных probes могут пересекаться.
Запись защищена от параллельного превышения лимита: максимум 128 событий на probe.
Если лимит исчерпан, отсутствие завершающего события не означает зависание.
Логи добавляют накладные расходы, особенно при частых ожиданиях; это диагностические
данные, а не измерение производительности сборки с выключенной диагностикой.

В лог не передаются адреса, имена файлов, ключи кэша, посты, cookies, содержимое медиа
или тексты исключений. Сборщик сохраняет модель телефона и версию Android без серийного номера.
`logcat -T 1` может добавить одну старую строку: учитывайте время начала сценария.

### Видео

- `OPEN`: вход в открытие движка, не точное время касания экрана.
- `GET_START`: постановка основного GET в существующий worker.
- `GET_HEADERS`: HTTP-статус; включает время до получения ответа, не отдельный DNS/TLS-замер.
- `GET_LENGTH`: размер из ответа в байтах, `-1` — неизвестен.
- `GET_FIRST_BYTES`: первая порция уже записана в существующий временный файл.
- `GET_COMPLETE`: последовательная загрузка завершена; значение — число байтов.
- `RANGE_REQUEST`: запрошенная позиция; `RANGE_HEADERS` — HTTP-статус.
- `RANGE_NO_VALIDATOR`: безопасный дополнительный запрос не выполнен из-за отсутствия валидатора.
- `RANGE_UNAVAILABLE`: ответ 200/416 вместо подходящего 206; основной GET продолжается.
- `RANGE_ERROR`/`GET_ERROR`: значение 1, если источник уже закрывался, иначе 0; это не классификатор причины ошибки.
- `READ_WAIT_START`: позиция отсутствующих байтов; `READ_WAIT_END`: длительность ожидания в **микросекундах**, включая случай отмены.
- `CONTAINER_END`, `STREAM_INFO_END`, `DECODER_OPEN_END`, `DURATION_SCAN_END`:
  длительность соответствующего вызова в **микросекундах**. END означает возврат,
  в том числе неуспешный, а не доказательство успешного открытия.
- `DURATION_SCAN_END` возникает только при фактическом сканировании подходящего
  полностью загруженного небольшого файла, а не при каждой проверке готовности.
- `INITIALIZE`/`INITIALIZED`: начало подготовки/получение результата на Main.
- `FIRST_OUTPUT`: первое уведомление обновления Android TextureView в этом открытии;
  не точное время физического показа пикселей дисплеем.
- `SOURCE_REUSED`: значение — probe старого источника. Его загрузка относится к старой
  метке, а новый decoder/read/first-output — к новой. `STOP` не равен отмене загрузки:
  источник может сохраняться для повторного открытия; `SOURCE_CLOSE` — его закрытие.

Связка долгого `READ_WAIT` к концу файла с отказом Range — свидетельство ожидания данных.
Большой `STREAM_INFO_END` сам по себе не доказывает нехватку CPU: внутри могло быть ожидание сети.
Сканирование длительности отмечено отдельно, поэтому его задержку можно отличить от загрузки.

### Изображения

События Coil подключены к общему app-owned ImageLoader: это также предзагрузки,
соседние страницы и другие его потребители, не только активный просмотрщик.
Каждое исполнение получает свой probe. Логи не содержат связь с конкретным URL;
для первого разбора открывайте по одному файлу, без параллельных экранов.

- `IMAGE_START` → `IMAGE_SUCCESS`/`IMAGE_ERROR`/`IMAGE_CANCEL`: исполнение запроса.
- `IMAGE_SIZE_START/END`: ожидание размера.
- `IMAGE_FETCH_START/END`: получение данных; это может быть диск, а не только сеть.
- `IMAGE_DECODE_START/END`: вызов декодера. Работа анимированного изображения после
  первого decode, GPU upload и физический показ этими callbacks не измеряются.
- `IMAGE_SUCCESS.value` соответствует Coil 3.3.0 DataSource:
  **0** — memory cache, **1** — другой источник в памяти, **2** — диск, **3** — сеть.
- При memory hit fetch/decode могут отсутствовать. При ошибке/отмене END этапа
  может отсутствовать: нельзя подменять его последним временем другого запроса.

Это не трассировка собственного ThumbnailLoader: его очередь/декодирование отдельно
не измерены. Существующее переиспользование готового превью сохранено.
