# История изменений в настройках

Экран «Список изменений» показывает все версии до установленной включительно,
в порядке убывания versionCode. Для каждой версии отображаются номер, дата,
разделы и пункты изменений; установленная версия отмечена подписью «Установлена».
История доступна без интернета и не подмешивает ещё не установленные обновления.

## Источник данных

Используются существующие `update/publishing/versions.json` и
`update/publishing/changelogs/ru/<code>.txt`. Задача приложения
`prepareChangelogHistory` автоматически копирует их в генерируемые assets
и подключена к assets каждого Android-варианта через Android Components API.
Отдельную вручную собранную историю вести не нужно. Старые файлы заметок
нельзя удалять: отсутствие файла выпущенной версии останавливает сборку.
При изменении версии задача удаляет устаревшие генерируемые файлы.

Существующий `app/src/main/assets/settings-changelog.txt` оставлен без изменений:
он по-прежнему проверяется штатной проверкой метаданных текущего релиза,
но экран читает полную историю из новых генерируемых assets.
Чтение и разбор выполняются на Dispatchers.IO; при ошибке показано сообщение,
повторное открытие экрана повторяет чтение. Запросов к сети нет.

## Область патча и проверки

Само изменение экрана истории не меняет DNS или номер версии. Объединённый
патч для 0.1.2 также содержит независимый DNS Архивача и исправление слишком
длинной строки AppNetworkStack, остановившей Detekt. Номер версии остаётся 0.1.2.
В release-request.json добавлена revision=2: изменение файла запроса запускает
новую сборку на master. Это не разрешение перезаписать опубликованный релиз.
Патч можно применять к исходникам 0.1.1 или поверх прежнего DNS-патча 0.1.2.
Новая история появится в заново собранном приложении, не в уже установленном APK.

Проверены в изолированной JVM/Compose-среде: разбор и порядок версий,
исключение будущих заметок, сохранение разделов, ошибки метаданных и файлов.
Исходники экрана скомпилированы с Compose compiler и граничными UI-фикстурами.
Сама Gradle-задача генерации проверена отдельно для кодов 1, 2 и 3,
повторного запуска с configuration cache и отсутствующего старого файла.
Проверены KtLint всего проекта, Detekt main/test изменённых модулей с теми же
параметрами --build-upon-default-config --parallel, что в CI, и штатные классы
source policy/release metadata в изолированных задачах. Это не полный Android LOCAL CHECK.

Добавлен Android runtime-тест `ChangelogHistoryRuntimeTest`: открытие истории
из settings, установленная версия, прокрутка до первого выпуска и возврат.
Без Android SDK 37/NDK и устройства он здесь не выполнен. Полная Android-сборка,
Android Lint и runtime-тест остаются отдельными обязательными проверками.
