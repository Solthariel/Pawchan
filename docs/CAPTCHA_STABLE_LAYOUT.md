# Стабильная капча (0.1.23)

## Контракт и ответственность

ComposerCaptchaSession — прежний lifecycle-владелец сетевого шага, отмены,
статуса и монотонного deadline. После ответа сервера чистая Kotlin-функция
готовит раскладку на Dispatchers.Default, затем с проверкой отмены публикуется
одно новое состояние. UI не сортирует варианты и не сопоставляет изображения.
Диспетчер явно внедряется в тестах; в приложении не вводится новый scope/кэш.

Список challenge.options сохраняет авторитетный серверный набор. Отдельный
keyboard содержит визуальные ячейки, в каждой — актуальный server number и
изображение. Lazy key — номер постоянной ячейки, не server number. Нажатие
отправляет server number; сессия проверяет его в текущем challenge.options.
Число колонок остаётся 4, начальная сетка не получает искусственных вариантов.

Совпадение изображений строгое: contentHashCode ускоряет поиск, contentEquals
проверяет реальные байты и исключает смешивание символов при коллизии. Очередь
для каждого изображения сохраняет кратность одинаковых картинок. Новые варианты
занимают свободные ячейки после закрепления всех сохранившихся; при уменьшении
набора пустые места не содержат старых кнопок и не принимают нажатия. Рост набора
не скрывает новые варианты. Размер в пределах задания не уменьшается.

Это самостоятельная реализация на Kotlin, без переноса Java-функции Dashchan,
Bitmap.sameAs, OCR, распознавания символов или автоматического выбора ответа.
Сравнение байтов не отождествляет лишь похожие изображения. Если сервер меняет
кодирование при тех же пикселях, такая картинка консервативно считается новой;
пиксельное декодирование и дополнительный bitmap-кэш для этого не вводятся.

## Отсутствие лишнего мигания

При одинаковых байтах taskImage переиспользуется прежний ByteArray. Совпавшие
плитки также сохраняют прежние модели изображений; AsyncImage остаётся в той же
ячейке и не получает новую модель только из-за перестановки на сервере. Блокировка
кнопок сохраняет semantics disabled и прежние цвета, без затемнения всей сетки.
Во время сетевого ожидания контент вообще не заменяется. Нижнего отдельного
CircularProgressIndicator нет: остаётся штатная строка «Проверка капчи…».

Настоящее изменение картинки публикуется, новое задание/ручной refresh сбрасывает
раскладку и выбор. Срок не продлевается от перестановки/новых ByteArray, срок
задания не подменяется сроком решённого токена. Старый ответ отменённой операции
не может заменить новую капчу. При успехе выдаётся только серверный токен.
