# Pawchan — основная Release-сборка

Release использует имя **Pawchan** и основной application ID
`com.solthariel.pawchan` (без суффикса). У него включены R8/minification,
resource shrinking и `debuggable=false`.

Debug для instrumented tests остаётся отдельным приложением **Pawchan Debug**
с пакетом `com.solthariel.pawchan.debug`, поэтому тестовые данные, база и PIN
не пересекаются с основным приложением.

## Переход с Pawchan Dev

В прежнем рабочем выпуске использовался пакет `com.solthariel.pawchan.dev`.
Изменение исходников **не переносит** его данные в `com.solthariel.pawchan`.
Обе установки могут оставаться на устройстве отдельно. Сохраните нужные
данные перед удалением старой установки; автоматическую миграцию мы не заявляем.
Ранее опубликованные changelog-заметки остаются исторически точными.

Существующий Pawchan с пакетом `com.solthariel.pawchan` сможет обновиться
только при соблюдении двух условий Android: новый APK подписан **тем же
сертификатом**, а его versionCode выше установленного. Собственный debug-ключ,
который может применяться к локальному `assembleRelease` без секретов,
**не годится** для обновления публичного Pawchan. Нельзя удалять установленное
приложение ради обхода ошибки подписи без резервной копии.

## Обновления

«О приложении» → проверить → скачать → установить через системный установщик
Android. Feed, история и APK должны быть доступны по HTTPS без авторизации.
Адрес feed задаётся `UPDATE_MANIFEST_URL`. Закрытый репозиторий не может быть
анонимным источником: недоступный feed даст обычную ошибку.

Проверки SHA-256, размера, идентификатора пакета, версии и сертификата APK
сохранены. APK скачивается только по нажатию; установка требует системного
подтверждения. Первое распространение без проверки соответствия подписей,
прав на native-компоненты и полного прогона тестов не допускается.
Apache/LLVM-уведомления для libmpvKt и Android NDK доступны в разделе лицензий
приложения; это не подтверждает, что лицензии всех native-зависимостей проверены.

## Проверки перед выпуском

Руководствоваться [процессом разработки](DEVELOPMENT.md) и
[проверкой выпуска](RELEASE.md): полный LOCAL CHECK, три Python-набора,
все Android instrumented tests на устройстве и разбор свежих отчётов.
Публикация и push требуют отдельного разрешения после полного прогона.
Старые release-заметки об авторизованных обновлениях описывают прежнее
состояние, а не действующую функциональность.
