# Подготовка и отправка вложений

## Владельцы и лимиты

[Composer](../../feature/composer) владеет UI-сессией и подготовкой текущего выбора;
app хранит черновики и связывает результат с тредом. Внедрённые repositories и
ImageLoader не извлекаются через service locator. Граница —
[MODULE_BOUNDARIES.md](../contracts/MODULE_BOUNDARIES.md).

`max_files_size` (KiB) у текущего адаптера 2ch — общий бюджет вложений, не лимит
каждого файла. Per-file/selection/file-count safety limits остаются отдельными.
Допуск считается по точным байтам подготовленных файлов, не округлённой подписи.

ComposerUploadPreparation выполняет конечные latest-selection jobs у владельца.
Кэш связывает identity исходника и опции обработки; отправка использует те же
подготовленные байты, не повторяет случайное изменение хеша. Отмена достигает
job и проверяется между преобразованиями; синхронный bitmap codec не становится
прерываемым только из-за coroutine. Ошибка оставляет выбор редактируемым.

PNG trailer после IEND не является сам по себе основанием отклонять изменение
хеша; очистка метаданных удаляет trailer. Повреждённая структура отклоняется.
Исходный файл не меняется. Ошибка не объявляет любой неизвестный PNG исправленным.

PostingUploadTracker учитывает media bytes, переданные транспорту, не время,
не multipart headers и не подтверждение получения сервером. HTTP replay сбрасывает
счётчик; поздний callback после отмены не обновляет новую попытку. 100% означает
переход к ожиданию ответа, не успешный пост.

## Проверки

Точный предел/один байт сверх него, изменение опций и invalidation кэша, ошибка
преобразования, отмена/закрытие, повторная отправка, HTTP replay, сеть и капча.
Состояние/раскладка капчи — [CAPTCHA_STABLE_LAYOUT.md](../CAPTCHA_STABLE_LAYOUT.md),
picker исключение — [APP_LOCK.md](APP_LOCK.md). Старые результаты и подробности:
[подготовка/прогресс](../history/UPLOAD_AND_UNLOCK_STABILITY.md) и
[PNG/lifecycle](../history/LOCK_COMPOSER_PATCH.md).
