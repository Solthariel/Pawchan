# Проверка перед выпуском

Это постоянный чек-лист, не отчёт о прохождении проверок конкретной версии.
Версия и code читаются из [versions.json](../update/publishing/versions.json),
а не из заголовков старых документов. Новый номер этим документом не назначается.

1. Проверить один связный набор изменений, совместимость данных и актуальный changelog.
2. После каждого патча выполнить [всю обязательную цепочку](DEVELOPMENT.md#обязательный-порядок-после-каждого-патча):
   LOCAL CHECK всех модулей → три Python-набора → полный device-smoke всех
   AndroidTest-модулей, не только изменённого. Отдельный APK/Detekt/фокусный тест
   не заменяет этот порядок.
3. Проверить свежие XML/HTML и фактическое выполнение каждого набора/модуля.
   Failures/errors, отсутствующие/старые отчёты и неразобранные skipped блокируют
   отправку. Дополнительно выполнить целевые runtime/native-host проверки;
   для hot path — [release-замеры](contracts/PERFORMANCE.md).
4. При любом исправлении повторить весь прогон на окончательных исходниках.
   Записать команды, среду, устройство, числа тестов, результаты, отчёты и блокеры.
   Старый PASS из [исторического отчёта](history/RELEASE_0_1_0.md) или другой
   исходной папки не подтверждает новый патч.
5. Показать результаты владельцу и получить отдельное разрешение отправки.
   Только затем готовить выпуск по [единому процессу](RELEASE_PROCESS.md).
   Это единственная операционная инструкция commit/push/восстановления публикации.
   Нет полного результата — статус «не полностью проверен», без push/публикации.

Не меняйте release-request ради документационного патча и не перевыпускайте
рабочий APK для исправления описания. Локальная подготовка, push, успешная
сборка и подтверждённая публикация — разные состояния.
