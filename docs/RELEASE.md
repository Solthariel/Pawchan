# Подготовка выпуска 0.1.0

## Версия

- Публичная версия: `0.1.0`; внутренний `versionCode`: `1`.
- Источник номера, кода и даты: `update/publishing/versions.json`.
- Текст выпуска: `update/publishing/changelogs/ru/1.txt`.
- Его копия в приложении: `app/src/main/assets/settings-changelog.txt`.
- `verifyReleaseMetadata` проверяет их совпадение и согласованность манифеста.
- Обычная пересборка не увеличивает номер. Процесс следующего выпуска описан
  в [системе выпусков](../update/publishing/README.md).

Пользовательский список изменений описывает первый выпуск, а не историю
внутренних правок. Прежние отчёты о промежуточных сборках в поставку не входят.

## Данные и интерфейс

Резервные копии `.pawbackup`, защита паролем, выбор разделов и замена выбранных
данных при восстановлении сохранены. Журнал отката остаётся в приватном
хранилище приложения. Перед изменением данных синхронизируются файл журнала
и каталог; ошибка синхронизации не игнорируется. Android использует
`android.system.Os`, JVM-тесты — отдельную контролируемую реализацию границы
синхронизации. Windows-тесты больше не открывают каталог через `FileChannel`.

Статистика автоскрытия показана стандартным Material 3 `AlertDialog`.
Поясняющий абзац, вложенная карточка и крупные отступы убраны. Остались
счётчики, статистика досок, один прокручиваемый блок и подтверждение сброса.

## Фактически выполненные проверки

- KtLint 1.8.0: исходники Kotlin и Gradle-скрипты.
- Detekt 1.23.8: штатная область проекта `src/main` и `src/test`.
- `VerifySourcePolicy`: неизменённая проверка архитектурных ограничений,
  выполненная отдельно от Android-конфигурации.
- `VerifyReleaseMetadata`: проверка текущего выпуска; отдельно проверен отказ
  при несовпадающем встроенном списке изменений.
- Семь Python-тестов инструментов версий и текущих метаданных.
- 102 JVM-теста на отдельном проверочном стенде: 0 ошибок, 0 пропусков.
  В их числе откат, повторное восстановление после отказа, ошибка синхронизации
  до изменения данных и отмена coroutine после сохранения журнала.
- На том же стенде с реальными Compose-зависимостями скомпилированы изменённые
  компоненты диалога статистики и существующий интерфейс резервного копирования.

Отдельный стенд использует API jar Android 36, заглушки host-компонентов и
ограниченный набор исходников. Он не является Android-сборкой приложения,
проверкой KSP/Room, R8, Lint или подтверждением независимости всех модулей.
Дополнительный анализ `androidTest` вне штатной области Detekt обнаруживает
замечания в существующих тестовых исходниках; он не объявлен успешным.

## Что ещё обязательно проверить

**LOCAL CHECK: FAIL** — штатный `scripts/local-check.sh` остановился на
`assembleDebug`: в среде подготовки отсутствует Android SDK (`SDK location
not found`). Полный SDK 37, NDK и CMake не установлены. Ограничения проекта,
проверки и предупреждения компилятора ради обхода этой ошибки не ослаблялись.

На машине с окружением из [README](../README.md):

```powershell
.\scripts\local-check.ps1
```

Только `LOCAL CHECK: PASS` подтверждает прохождение полной штатной проверки.
Отдельно нужны instrumented-тесты и проверка на ARM64-устройстве, включая
`BackupDirectorySyncTest`, окно статистики, восстановление копии и перезапуск
после прерванной операции. Windows и Android-устройство в среде подготовки
не запускались.

Архив содержит подготовленные исходники, а не проверенный подписанный APK.
Подпись, выпуск APK и публикация ещё не выполнены; URL и хеш пакета в
манифесте не подставлены фиктивно.
