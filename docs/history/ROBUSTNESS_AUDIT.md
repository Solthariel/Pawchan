# Защита фильтрации, превью и сессий капчи — 0.1.21

> Исторический снимок конкретного патча/проверки, не инструкция для текущего выпуска.
> Числа PASS/FAIL относятся только к указанной в отчёте базе и среде.
> Старые команды применения/публикации не выполнять; см. [карту действующих документов](../README.md).

## Контракты

- ORDERED не обрезает текст поста. Без ограничения расстояния применяется
  последовательный поиск; с ограничением — очередь вхождений и связанные узлы
  предшественников. Префиксы цепочек не копируются на каждом вхождении.
  Из нескольких допустимых цепочек выбирается одна корректная; точные диапазоны
  подсветки при неоднозначном совпадении могут отличаться от прежних.
- Валидация условий отклоняет более 128 значений или исключений либо более 32768
  UTF-16 символов суммарно. Условия за пределами лимита не исполняются движком; редактор показывает
  ошибку валидации при их сохранении.
  Это не лимит длины поста. Production-фабрики треда, каталога и превью по-прежнему
  передают Default dispatcher для подготовки представления и фильтрации.
- ThreadHistoryController принадлежит тому же viewModelScope и использует тот же
  requestMutex, что обновление треда. Хранилище и представление не переезжают в
  глобальный scope. После отмены устаревший результат не передаётся экрану.
- В одном живом окне превью исчезновение исходного поста при обновлении не
  стирает показанный снимок. Смена target не переносит снимок чужого поста.
  Правило трёх живых окон и облегчённого состояния старых окон не меняется.
- Капча проверяет отмену после каждого асинхронного ответа до записи состояния.
  Это защищает и от реализации репозитория, поздно возвращающей ответ после cancel.
  Deadline задания остаётся монотонным и временным; принятый сервером решённый
  токен не получает срок задания. Протокол капчи остаётся у адаптера источника.
- Публичные адресные входы 2ch и Архивача проверяют логический SiteId до HTTP.
  UnsupportedSite — domain-ошибка, не выдуманный HTTP-статус. UI не выбирает
  протокол по тексту сообщения. Нормализация OP/sage остаётся в data/network.
  Это защита границ существующего адаптера, не реализация второго сайта.

## Ограничения проверки

JVM-тесты и Robolectric не являются instrumented-прогоном на телефоне.
В среде подготовки нет подключённого Android-устройства или эмулятора.
Device smoke и сравнительный release Macrobenchmark (не менее 5 повторов,
CPU/overrun распределения и trace) остаются обязательными перед полным признанием
проверки производительности. Performance PASS и отсутствие микроподёргиваний
на основании этих изменений не заявляются.

## Дополнение той же версии: живая история изменений

Экран настроек владеет единым контроллером истории. UpdatePanel передаёт найденный
versionCode через явный callback; общий StateFlow обновляет уже открытый диалог.
Когда кеш ещё не содержит найденную версию, история запрашивается по URL с этим
кодом без старого валидатора и с no-cache. Устаревший ответ или 304 без нужной
версии не заменяют корректный кеш; открытие диалога повторяет попытку.

Регрессии: ChangelogHistoryControllerTest (обнаружение версии, параллельное
открытие, устаревший ответ и offline), ChangelogHttpTest (параметр версии,
сохранение параметров URL и заголовки), ChangelogHistoryRepositoryTest (304 без
ожидаемой версии), ChangelogHistoryRuntimeTest (появление новой версии в открытом
диалоге и повторное открытие без перезапуска приложения).


## Автопроверка при входе в «О программе»

Новый визит создаёт UpdateCheckRequest. Controller/ViewModel обновлений находится
выше lazy-строк и не зависит от видимости панели. Проверка запускается один раз
для визита, повторный вход создаёт следующий запрос; состояния скачивания и
готового APK не сбрасываются автопроверкой. Обработчик обнаружения версии связан
с общим контроллером истории явным callback, без глобальной шины событий.

История предзагружается параллельно. Mutex и метка успешно проверенного визита
объединяют вход и открытие диалога: успешная загрузка не повторяется при каждом
открытии списка. Новая версия, ещё отсутствующая в истории, требует адресной
перепроверки. Неудачная загрузка допускает повтор при открытии списка.

UpdateEntryChecksTest закрепляет один запрос на визит, новый вход, отсутствие
автопроверки вне раздела и сохранение скачиваемого/готового APK. Дополнительный
сценарий ChangelogHistoryControllerTest проверяет предзагрузку до открытия диалога,
повторное открытие и новый визит без дублирующих запросов.

Через временный Robolectric harness дополнительно проверен настоящий
UpdateViewModel + UpdateClient с детерминированным HTTP interceptor: автопоиск
даёт Available, тот же визит не создаёт запросов, новый визит и ручная повторная
проверка создают по одному запросу. Ошибка не запускает цикл повторов; ручная
попытка после неё работает. Ни один автоматический запрос не обращается к APK.
Временные harness-копии и зависимости в ZIP не включаются.
