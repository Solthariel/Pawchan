# Технический аудит Pawchan 0.1.27

## Область и статус

Основа — предоставленный архив Pawchan-0.1.27.zip, GitHub source revision
`3d809c661e190b8114f05cdc03945a21f0f2734a`. Правила взяты из AGENTS.md.
Проверены граф Gradle-зависимостей, штатные source guards, структурные лимиты
Kotlin, а также подробно — жизненный цикл обновлений и его тестируемость.
Это не построчный аудит всех подсистем, аудит безопасности native-кода или
доказательство отсутствия других ошибок.

Статус: код подготовлен для проверки, НЕ полный LOCAL CHECK: PASS.
Нет установленного Android SDK и подключённого устройства. Штатная проверка
действительно запускалась и остановилась на assembleDebug: SDK location not found.

## Граница ответственности после рефакторинга

- UpdateViewModel владеет UI-state и ViewModel scope. Внутренний UpdateOperations
  задаёт операции check/download/close и имеет реального production-потребителя.
- UpdateClient оркестрирует проверку версии, URL, транспорт, download store и verifier.
- UpdateTransport владеет выделенным OkHttpClient, отменой, чтением и освобождением
  его ресурсов. App-owned GitHub DNS остаётся заимствованной зависимостью.
- UpdateDownloadStore владеет каталогом обновлений, partial каждой попытки и
  атомарной заменой кандидата после верификации.
- copyUpdateStream отвечает только за лимит байтов, progress и checkpoints отмены.
- UpdateVerifier по-прежнему проверяет длину, SHA-256, package id, versionCode,
  versionName и сертификаты подписанта. Эти проверки не заменены тестовыми fake.

Новых Gradle-модулей, production-зависимостей, публичных API или глобального
состояния нет. Детали остаются internal внутри существующего :update. Перенос
UI-навигации в domain и новый универсальный core/utils не требуются.

## Что соблюдается в проверенной области

- Граф project dependencies ацикличен; :domain и :core:ui не имеют project-зависимостей.
- :feature:thread зависит только от :domain, :core:ui и :core:media.
- :feature:composer и :core:media не импортируют app через Gradle dependency.
- Штатный VerifySourcePolicy не обнаружил перечисленные в нём запрещённые шаблоны.
  Это НЕ доказательство истинной отмены, плавности или корректности всех owners.
- В просмотренных Kotlin sources не найдено GlobalScope и подавлений @Suppress /
  @SuppressLint. Правила, thresholds, dependency guards и Lint-конфигурация не изменены.
- Проверки версии/публикации сохранены; build.yml не восстановлен. Единственный
  workflow остаётся Publish signed release. Версия не повышена, релиз не запущен.

## Оставшийся технический долг: следующие отдельные батчи

### 1. Владение сетевыми ресурсами app

AppNetworkStack.close запускает собственный Thread для TLS/cache cleanup и не
предоставляет проверки завершения cleanup. Рекомендуется отдельно описать close
contract всего stack: идемпотентность, отмену borrowers, ожидание фонового освобождения
и тест повторного закрытия. Нельзя просто перенести evictAll обратно на Main.
В этом патче исправлен только владелец :update, не весь сетевой stack.

### 2. Общая механика сервисного DNS

ArhivachDnsSelector и GithubDnsSelector дублируют resolver state, update и fallback;
GitHub использует createDohResolver, размещённый в файле Arhivach. Рекомендуется
выделить внутренний адаптер сервисного DNS с отдельными host policies, а bootstrap
создавать из транспорта, который явно не наследует форумные interceptors/auth/cache.
Перед изменением — тесты origin isolation, системного fallback, смены профиля и
workers. Не объединять независимые профили настроек и не вводить новый глобальный DNS.

### 3. Согласование UI-разделителей с правилами

AGENTS.md запрещает U+00B7 в собственных интерфейсных подписях, однако metadata
SUMMARY_SEPARATOR в MediaMetadata.kt использует ` · `, и это закреплено текущими
MediaMetadataTest. Это реальное расхождение кода с правилом; текст пользовательских
постов менять нельзя. Отдельно согласовать замену в UI и соответствующие expectations.
Здесь production-формат метаданных не изменён и никаких визуальных PASS не заявлено.

### 4. Граница composer/network

:feature:composer пока использует :data:network для PostingMediaBytes. AGENTS.md
явно отмечает это как временное исключение. Следующий архитектурный батч должен
определить владельца получения attachment bytes, cancellation и borrowed resources,
а не просто переместить файл ради исчезновения dependency.

### 5. Проверка Android end-to-end

Нужны штатный LOCAL CHECK и runtime сценарии: закрытие владельца во время медленной
загрузки, повторное открытие настроек, отмена во время проверки, повреждённый APK,
смена GitHub DNS, установка подписанного APK на Samsung. Host-тесты этого не заменяют.
Файловый commit не обещает durability при потере питания; синхронный платформенный
verifier не становится мгновенно прерываемым — отмена проверяется до и после него.
