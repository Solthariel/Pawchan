# Pawchan 0.1.52: исправленная версия исходников

Это исходники с изменениями по 15 пунктам ревью, не официальный релиз и не готовый APK. Версия оставлена прежней, 4chan только для чтения. Debug ставится как `com.solthariel.pawchan.debug`, отдельно от релиза; Android 11+, ARM64.

## Ответы @monkey на Дваче

- Серверное поле `comment` разбирается структурно: отдельным ответом считается только `div.neuroslop` в посте Двача. Обычное упоминание `@monkey` в тексте или цитате не меняет оформление. Для 4chan и страницы стороннего архива это правило не включено.
- По умолчанию ответ виден: «Ответ @monkey», лёгкая подложка и рамка с акцентной полосой. Ссылки, вложенное форматирование, спойлеры и абзацы остаются частью одного выделяемого текста. В компактном каталоге используется текстовая подпись.
- **Настройки → Интерфейс → Отображение → Скрывать ответы @monkey** убирает только размеченный ответ. Вопрос, ссылки автора, номер поста и вложения не скрываются. Переключатель сохраняется между запусками; его можно выключить, не загружая пост повторно, если разметка уже есть в кэше.
- Это настройка отображения, а не удаление данных и не команда серверному боту. В новой копии и истории сохраняется принадлежность фрагментов; старые офлайн-копии, записанные до этой доработки без разметки, не пытаются угадывать автора. Чтобы разметка появилась, нужно получить пост заново и при необходимости обновить сохранённую копию.
- Пример разметки поста №2773740 включён в `data/network/src/test/resources/fixtures/dvach-monkey-2773740.html`. Добавлены тесты на настоящий путь декодирования ответа API, пропуск обычных упоминаний, два блока, ссылки и спойлеры, светлые/тёмные цвета, скрытие в каталоге и открытом треде, восстановление состояния настроек и копий. Kotlin/Compose-тесты в этой среде не запускались.

## Где взять debug APK

1. Распакуйте архив в свой репозиторий. В корне должны быть `gradlew`, `settings.gradle.kts` и `.github/workflows/build-debug.yml`, а не один ZIP. Для изолированной проверки подойдёт приватный репозиторий с основной веткой `main`. Workflow должен находиться в основной ветке, Actions должны быть включены. Для debug **не нужны релизные секреты или изменение release-request**. Унаследованный релизный процесс исходного проекта может реагировать на изменение `release-request.json` в `master`; его запуск не нужен.
2. **Actions → Build debug APK → Run workflow**. Выберите ветку, содержащую исправленные исходники. Запуск выполняется в вашем репозитории с вашими правами.
3. После успешного прогона скачайте из раздела **Artifacts** пакет `Pawchan-debug-arm64-<номер запуска>`. В нём `app-debug.apk` и `app-debug.apk.sha256`. При красном прогоне APK не считается собранным: смотрите лог упавшего шага.
4. Используется debug-подпись runner, не релизная подпись. Между разными временными runner debug-ключ может отличаться. Для обновления установленной debug-версии с сохранением данных используйте постоянный собственный debug-ключ; не удаляйте установку с нужными данными без копии.

Runner устанавливает Java 25, Android SDK 37, Build Tools 37.0.0, NDK 29.0.14206865 и CMake 3.22.1. Затем проверяет Python-тесты, пересобирает JNI, запускает JVM unit-тесты, собирает debug APK и инструментальные тесты приложения, проверяет подпись и идентификатор пакета. Инструментальные тесты **компилируются, но не запускаются** в этом workflow. Публикации в Releases нет.

## JNI и локальная сборка

В архиве сохранены исходные готовые `.so` и исходные хеши. Изменён **исходник** JNI. Ручной workflow пересобирает мост и обновляет в рабочей копии хеш только `libmpvkt_jni.so`. Обычный Run в Android Studio без пересборки моста использует старый бинарник. Для полной локальной debug-сборки на Linux x86-64 с указанными инструментами:

```sh
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/29.0.14206865"
bash scripts/rebuild-debug-jni.sh
chmod +x gradlew
./gradlew :app:assembleDebug
```

Вывод: `app/build/outputs/apk/debug/app-debug.apk`.

## Изменения

| Пункт | Что изменилось |
|---|---|
| NAV-01 | Архивач открывается отдельным маршрутом с сайтом и доской. Стрелка и системная кнопка возвращаются по стеку. Внутреннее закрытие поиска/треда и отдельный вход из загрузок сохранены. |
| DRAFT-01 | Отмена импорта освобождает блокировку формы. Номер конкретной операции и номер сессии не дают позднему результату переписать новый черновик. |
| COPY-01 | Повторный запрос с медиа добавляется к цепочке WorkManager. Сообщение «файлы в очереди» выводится после подтверждения постановки. |
| SAVE-01 | Новая загрузка в папку сначала пишет во временный файл приложения. Только после успешной передачи создаётся итоговый документ. При сбое его записи приложение пробует удалить только созданный им документ. Не все внешние провайдеры разрешают удаление; старые URI для давно поставленных загрузок не удаляются. |
| HIST-01 | История из экрана и фоновых обновлений использует общую сериализацию по каталогу хранилища и единое чтение, слияние и запись снимка. |
| READ-4C-01 | Декодирование каталога и тредов 4chan перенесено с вызывающего UI-потока. Прирост плавности не измерялся. |
| READ-4C-02 | Кэш и HTTP-валидатор сохраняются только для успешно разобранного ответа. Интервалы обращения к сайту не менялись. |
| REL-01 | Несовпадение запроса и реестра останавливает retry до подтверждения; при подготовке дополнительно проверяется подтверждённая цель. |
| PREF-01 | Экран статистики показывает ошибку, если настройку `/postcount` не удалось записать. |
| REL-02 | Обе оболочки упаковки используют общий валидатор URL, прямой Gradle-вход также проверяет HTTPS, хост и допустимость значения. |
| MEDIA-01 | Поздно созданный движок Vocaroo/Cronet не остаётся у уже закрытого владельца. |
| MEDIA-02 | Объекты состояния нативных потоков удерживаются до завершения ядра mpv и тогда освобождаются. Требует пересборки JNI, см. выше. |
| TABS-01 | В поиске заголовок раскрытого раздела «Треды» не меняет скрытую настройку сворачивания. |
| WATCH-01 | Ошибка автоматической проверки открытого треда отображается рядом с контентом. Ошибка ручного обновления остаётся отдельным случаем. |
| ARCH-RESULT-01 | Неуспешный ответ со случайной ссылкой больше не принимается за подтверждение архивирования. Различаются успешный редирект, подтверждение, ранее добавленный тред и ошибка. |

Теги и вход в архив задаются возможностями источника. Старый `withLocalVideo`, у которого не было вызовов из приложения, перенесён в тестовые исходники, не в APK. Миграции данных сохранены; постинг на 4chan и новые языки не добавлялись.

## Как проверить на устройстве до выпуска

- На неглавной доске Двача прокрутить каталог, открыть Архивач, сравнить стрелку и системный Back. Повторить с открытым поиском, архивным тредом и после переключения вкладки.
- Во время импорта вложения в ответ открыть ссылку на другой тред и вернуться: прежний текст сохранён, форму снова можно редактировать.
- Поставить две копии с медиа подряд и открыть обе без сети после окончания очереди. При отмене отдельной загрузки проверять реальную выбранную папку и повторную попытку.
- Проверить одновременное обновление избранного, поиск разделов и ошибку сохранения `/postcount`. На длинном треде измерить кадры и проверить повтор после нечитаемого ответа.
- Проверить просмотр, перемотку, PiP и возврат на ARM64. Для проверки нативной правки использовать APK **после пересборки моста**.

Фактические проверки в среде без Android SDK см. в `docs/PATCH-LOCAL-CHECKS.txt`. Сборка Kotlin/Android, выполнение на телефоне, замеры производительности и пересборка нативного бинарника здесь не выполнялись.
