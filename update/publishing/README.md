# Выпуски и обновления Pawchan

## Версия и порядковый номер

Начальная версия — **0.1.0**, внутренний `versionCode` — **1**. Версии `0.x.y` обозначают начальную
разработку до первого стабильного контракта `1.0.0`; это не обещание стабильности API.
Отметки MVP и номера рабочих патчей не входят в название приложения или APK.

Публичная версия имеет строгий вид `MAJOR.MINOR.PATCH`, без ведущих нулей:

* PATCH: исправление ошибки без новой функциональности и нарушения совместимости.
* MINOR: новая обратно совместимая функциональность; PATCH сбрасывается в 0.
* MAJOR: несовместимое изменение; MINOR и PATCH сбрасываются в 0.

Для серии `0.x.y` несовместимые экспериментальные изменения следует явно описывать
в changelog; при готовности стабильного публичного контракта выпускается `1.0.0`.
В рамках проекта совместимость включает сохранённые данные, настройки, черновики
и поддерживаемые контракты. Само увеличение версии не заменяет миграции.

Порядковый номер `versionCode` независим от трёх чисел SemVer и увеличивается
на 1 для каждого нового выпуска APK: 1, 2, 3… Это не номер запуска приложения
и не счётчик локальных пересборок. В интерфейсе отображается только `0.1.0`; внутренний номер там не показывается.

## Источники данных

* `versions.json` — единственный источник версии, порядкового номера и даты.
* `changelogs/ru/<versionCode>.txt` — описание конкретного выпуска.
* `app/src/main/assets/settings-changelog.txt` — описание текущего выпуска в приложении.
* `manifest/data-v1.json` — опубликованные пакеты с адресами, размером и SHA-256.

Gradle получает версию из `versions.json`. `verifyReleaseMetadata` проверяет
строгий формат, уникальность номеров и согласованность данных текущего выпуска.

## Единая команда выпуска и восстановления

Актуальная инструкция: [docs/RELEASE_PROCESS.md](../../docs/RELEASE_PROCESS.md).

```powershell
.\scripts\Publish-Release.ps1 -Change patch -NotesFile "$env:USERPROFILE\Downloads\release-notes.txt"
# После сбоя, без новой версии:
.\scripts\Retry-Release.ps1
```

Обе команды запускают существующий Publish signed release через push-коммит в master.
Публикация не запускается вручную и не заменяет ранее опубликованный APK.
bump_version.py остаётся внутренним валидатором подготовки версии, но ручная
цепочка bump/add/commit/push больше не является рекомендуемой инструкцией.
Публичная лента формируется из проверенных release assets; история не дублируется.
